# قالب‌های لندینگ PGL

لندینگ‌های بسته `pgl-landing-package-v1.0.zip` با همان طراحی در پروژه قرار گرفته‌اند. محتوای هر دو محصول و کاتالوگ مشترک از سیستم تنظیمات پروژه خوانده می‌شود. داده‌های اصلی بسته، پیش‌فرض این تنظیمات هستند. قالب‌های `resources/views/templates` آن‌ها را به سیستم برگه‌های پروژه معرفی می‌کنند.

## استفاده در مدیریت

در ایجاد یا ویرایش برگه، از فهرست قالب یکی از این گزینه‌ها را انتخاب و برگه را منتشر کنید:

- «لندینگ PGL Ultimate 27» (`pgl-ultimate`)
- «لندینگ PGL FIFA 23» (`pgl-fifa-23`)

قالب‌ها HTML مستقل بسته را نمایش می‌دهند. متن، قیمت، لینک‌ها و ترتیب بخش‌ها از تنظیمات لندینگ در پنل خوانده می‌شوند؛ محتوای ویرایشگر برگه جایگزین این تنظیمات نمی‌شود. لینک‌های داخلی به مسیرهای اصلی محصولات اشاره دارند، حتی اگر برای برگه اسلاگ دیگری انتخاب کنید.

## ویرایش محتوا در پنل

از منوی «تنظیمات ← لندینگ‌های PGL» وارد شوید (`/admin/settings/product-landings`). چهار زبانه وجود دارد:

- **PGL Ultimate 27:** اطلاعات محصول، سئو، دکمه‌ها، منو، بخش‌های محتوا و پاورقی این محصول.
- **PGL FIFA 23:** همان تنظیمات، مستقل از محصول اول.
- **صفحات جزئیات مشترک:** تصاویر، معرفی و آمار صفحات لیگ‌ها، استادیوم‌ها، جام‌ها و چهره‌ها.
- **کاتالوگ:** مشخصات لیگ‌ها، تیم‌ها، استادیوم‌ها و جام‌ها، تصاویر و بلوک‌های محتوای تیم‌ها.

هر بخش باز و بسته می‌شود. متن فارسی و انگلیسی فیلد جدا دارد. موارد فهرست‌ها قابل افزودن، حذف و جابه‌جایی هستند؛ «افزودن» یک نمونه از همان نوع می‌سازد که باید محتوایش را ویرایش کنید. تصاویر از کتابخانه رسانه انتخاب می‌شوند یا آدرس تصویر را وارد می‌کنید. تغییرات پس از ذخیره در صفحات اصلی، جزئیات و قالب برگه‌ها اعمال می‌شوند. نوع بخش و تم رنگی برای حفظ ساختار قالب ثابت‌اند.

اگر فرم دیگری همین تنظیمات را ذخیره کرده باشد، ارسال نسخه قدیمی با خطا متوقف می‌شود تا تغییرات جدید بازنویسی نشوند. پس از این خطا، صفحه را دوباره باز کنید.

## ذخیره‌سازی و پیش‌فرض‌ها

`ProductLandingsSettings` از `BaseSettings` ارث می‌برد و از همان جدول `settings`، `ArrayCast`، کش گروهی و `UpdateSettingAction` پروژه استفاده می‌کند. گروه `product_landings` شامل کلیدهای `ultimate`، `fifa23`، `pages` و `catalog` است. هر زبانه فقط کلید خودش را در یک تراکنش ذخیره می‌کند.

اگر مقداری ذخیره نشده باشد، کل محتوای اصلی از `config/product-landings.php` و `config/landing-catalog.php` خوانده می‌شود؛ نیازی به اجرای دستور مقداردهی یا نوشتن در دیتابیس اصلی نیست. فهرست خالی ذخیره‌شده خالی می‌ماند و موارد حذف‌شده از پیش‌فرض برنمی‌گردند. فرم داده را ساختاریافته ارسال می‌کند تا تعداد زیاد فیلدها به محدودیت `max_input_vars` برخورد نکند؛ مدیر با فیلدهای معمولی کار می‌کند.

مجوز خواندن و نوشتن `setting.product-landings` است و در `PermissionSeeder` و سایدبار ثبت شده است. مدیر کل مطابق روال پروژه دسترسی دارد؛ برای نقش‌های دیگر، پس از همگام‌سازی مجوزها با روال استقرار پروژه، این مجوز را به نقش موردنظر بدهید. این تغییر هیچ دسترسی‌ای را خودکار به نقش‌های دیگر نمی‌دهد.

## مسیرها

- `/pgl-ultimate` و `/pgl-fifa-23`: لندینگ‌های فارسی
- `/en/pgl-ultimate` و `/en/pgl-fifa-23`: نسخه‌های انگلیسی
- زیرمسیرهای `leagues`، `stadiums`، `trophies` و `faces`: جزئیات
- نمونه صفحه لیگ: `/pgl-ultimate/leagues/persian-gulf-pro-league`
- نمونه صفحه تیم: `/pgl-ultimate/leagues/persian-gulf-pro-league/sepahan-fc`

مسیرهای اصلی لندینگ از تنظیمات رندر می‌شوند و ساخت برگه لازم ندارند. برای همان اسلاگ‌ها، روت لندینگ بر روت CMS اولویت دارد. قالب برگه برای استفاده در اسلاگ‌های دیگر و پیش‌نمایش مدیریت نیز در دسترس است.

## محل فایل‌ها

- قالب‌های قابل انتخاب: `resources/views/templates/pgl-*.blade.php`
- ویوها و partialهای اصلی: `resources/views/front/landings`
- CSS و JavaScript اصلی: `resources/css/front/landing.css` و `resources/js/front/{landing,kit-viewer}.js`
- تصاویر اصلی: `public/images/landings`
- پیش‌فرض محصولات: `config/product-landings.php`
- پیش‌فرض کاتالوگ لیگ‌ها و تیم‌ها: `config/landing-catalog.php`
- گروه تنظیمات: `app/Infrastructure/Services/Setting/Groups/ProductLandingsSettings.php`
- اعتبارسنجی محتوای تودرتو: `app/Application/Content/Support/ProductLandingContentSchema.php`
- فرم مدیریت: `resources/views/admin/system/settings/product-landings.blade.php`
- آماده‌سازی داده قالب: `app/Application/Content/Actions/GetProductLandingPageDataAction.php`
- کنترلرها: `app/Http/Controllers/Front/Landings`
- ابزار مورد استفاده ویوهای اصلی: `app/Support/Landings.php`
- روت‌ها: `routes/front/landings.php`؛ قبل از catch-all محتوای سایت ثبت شده‌اند و فقط کلیدهای محصولات تعریف‌شده را می‌گیرند.

## نصب روی محیط دیگر

```bash
npm ci
npm run build
php artisan config:clear
php artisan route:clear
php artisan view:clear
```

دو وابستگی `alpinejs` و `three` در manifest و lock ثبت شده‌اند. فایل‌های CSS و JS لندینگ ورودی مستقل Vite دارند. فایل‌های تولیدشده در `public/build` مطابق روال پروژه در Git ثبت نمی‌شوند.

## نکات خود بسته

لینک‌های خرید و لانچر، اطلاعات نمایشی و تصاویر نمونه در مقادیر پیش‌فرض عیناً مانند بسته‌اند. برای اتصال خرید واقعی، لینک‌ها را در تنظیمات هر محصول ویرایش کنید. تغییرات ویوهای عمومی فقط برای خواندن داده و مسیر تصاویر از تنظیمات است؛ کلاس‌ها، چیدمان و افکت‌ها حفظ شده‌اند. کامنت معیوب Blade در `master.blade.php` نیز تصحیح شده است.

## بررسی

تست‌های مربوط، رندر هر دو زبان، صفحات جزئیات، قالب CMS، حفظ مسیرهای عمومی، برابری پیش‌فرض‌ها، ذخیره بدون تغییر، تغییر محتوا، استقلال محصولات، کش، حذف فهرست‌ها، اعتبارسنجی، مجوز و جلوگیری از بازنویسی نسخه قدیمی را بررسی می‌کنند.

```bash
php artisan test tests/Feature/Content/ProductLandingTemplateTest.php
php artisan test tests/Feature/Content/ProductLandingsSettingsTest.php
node --test tests/Frontend/product-landings.test.mjs
```
