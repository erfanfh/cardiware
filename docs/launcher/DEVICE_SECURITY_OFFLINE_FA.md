# امنیت دستگاه و مجوز آفلاین لانچر

## سیاست نهایی

- هر حساب فقط یک دستگاه فعال دارد.
- نخستین ورود تأییدشده، اسلات اول را ثبت می‌کند.
- انتقال به دستگاه دوم فقط یک‌بار و با OTP شماره موبایل حساب انجام می‌شود.
- بعد از انتقال، دستگاه اول و تمام Tokenهای آن فوراً باطل می‌شوند.
- اگر دستگاه اول هنوز مجوز آفلاین معتبر داشته باشد، دستگاه دوم آنلاین فعال می‌شود ولی
  صدور مجوز آفلاین آن تا زمان انقضای مجوز قبلی به تعویق می‌افتد؛ بنابراین دو پنجره
  آفلاین هم‌زمان صادر نمی‌شود.
- دستگاه سوم یا بازگشت خودکار به دستگاه اول رد می‌شود.
- حذف دستگاه از API کاربر غیرفعال است؛ Reset فقط توسط پشتیبانی انجام می‌شود.

کلید خصوصی ECDSA دستگاه با DPAPI کاربر ویندوز نگهداری می‌شود. سرور در هر ورود، امضای
درخواست، تازگی timestamp و یک‌بارمصرف‌بودن nonce را بررسی می‌کند. fingerprint سخت‌افزار
به‌تنهایی معیار مالکیت نیست و همراه Device Key استفاده می‌شود.

## استقرار

1. از دیتابیس و پوشه `storage/app/private` نسخه پشتیبان بگیرید.
2. افزونه OpenSSL در PHP باید فعال باشد.
3. Migrationها را اجرا کنید:

   `php artisan migrate --force`

4. در اولین صدور مجوز، کلید RSA-3072 در مسیر زیر ساخته می‌شود:

   `storage/app/private/launcher/offline-license-private.pem`

   این فایل خصوصی است، نباید داخل Git یا پوشه public قرار بگیرد و باید در Backup دائمی
   سرور باشد. پاک‌شدن آن باعث تغییر کلید امضا و ردشدن مجوزهای قبلی می‌شود. در استقرار
   چندسروری، همین دو فایل کلید باید از Storage مشترک خوانده شوند.

5. حداکثر زمان آفلاین در `.env` قابل کاهش است ولی بیشتر از ۷ روز نمی‌شود:

   `LAUNCHER_OFFLINE_LICENSE_DAYS=7`

در اولین ورود بعد از این به‌روزرسانی، نشست قدیمی بدون Device Key دوباره احراز می‌شود و
همان رایانه به‌عنوان دستگاه اول ثبت خواهد شد.

## Reset پشتیبانی

روش اصلی از داخل پنل مدیریت است:

`پنل مدیریت ← فروشگاه ← دستگاه‌های لانچر`

مدیر می‌تواند کاربر را با نام، موبایل، ایمیل یا ID پیدا کند، وضعیت دو اسلات و مجوز
آفلاین را ببیند و پس از واردکردن دلیل و تأیید مالکیت، Reset کامل انجام دهد. هر Reset
همراه مدیر انجام‌دهنده، IP، دلیل و Snapshot وضعیت قبلی در جدول
`launcher_device_reset_logs` ثبت می‌شود. دسترسی این صفحه با مجوز
`launcher-device.manage` کنترل می‌شود.

دستور Artisan فقط روش جایگزین اضطراری است:

`php artisan launcher:reset-device USER_ID`

برای اجرای غیرتعاملی:

`php artisan launcher:reset-device USER_ID --force`

این دستور هر دو اسلات، سابقه انتقال، دستگاه‌های فعال و Tokenهای لانچر را باطل می‌کند.
ورود تأییدشده بعدی دوباره اسلات اول خواهد بود. این دستور نباید در اختیار کاربر نهایی باشد.
اگر مجوز آفلاین قبلی هنوز منقضی نشده باشد، دستگاه جدید تا تاریخ انقضای آن فقط آنلاین
کار می‌کند و سپس مجوز آفلاین دریافت خواهد کرد.

## حالت آفلاین

- مجوز آفلاین RSA-امضاشده و به شناسه کاربر و fingerprint کلید عمومی دستگاه متصل است.
- اعتبار آن از آخرین بررسی آنلاین حداکثر ۷ روز است.
- کش محصول و مجوز با DPAPI همان کاربر ویندوز رمز می‌شوند.
- در حالت آفلاین فقط محصولات متعلق به همان حساب که قبلاً در لانچر باز و کش شده‌اند قابل
  مشاهده/اجرا و مدیریت ماد محلی هستند.
- دانلود، نصب محتوای جدید، دریافت آپدیت و پشتیبانی آنلاین همچنان اینترنت می‌خواهند.
- عقب‌بردن ساعت سیستم یا تغییر Device Key باعث رد مجوز و الزام اتصال آنلاین می‌شود.
