# ریست دستگاه و محرومیت حساب لانچر

## تفاوت دو عملیات مدیریتی

### Reset کامل دستگاه کاربر

این عملیات فقط هویت دستگاه‌های لانچر را از نو می‌سازد:

- Tokenهای لانچر کاربر باطل می‌شوند.
- دستگاه‌های قبلی `revoked` می‌شوند.
- کلید عمومی و Fingerprint اسلات اول و دوم پاک می‌شود.
- `active_device_slot` پاک و `device_transfer_used` دوباره `false` می‌شود.
- خریدها، سفارش‌ها، حساب سایت و فایل‌های نصب‌شده کاربر حذف نمی‌شوند.
- ورود آنلاین بعدی به‌عنوان دستگاه اول جدید ثبت می‌شود و یک فرصت انتقال دوباره در دسترس خواهد بود.
- علت، مدیر، IP و تصویر وضعیت قبلی دستگاه‌ها در تاریخچه Reset ذخیره می‌شود.

مجوز آفلاینی که پیش از Reset روی یک رایانه کاملاً آفلاین صادر شده، از راه دور قابل حذف آنی نیست و حداکثر تا تاریخ انقضای خودش معتبر می‌ماند. با اولین اتصال آنلاین یا پایان مهلت آفلاین، دستگاه باید دوباره تأیید شود.

### محرومیت حساب از لانچر

این عملیات مستقل از Reset دستگاه است:

- فقط دسترسی حساب به لانچر بسته می‌شود؛ ورود به خود سایت همچنان مجاز است.
- علت محرومیت و دائمی یا زمان‌دار بودن آن ثبت می‌شود.
- Tokenهای لانچر فوراً باطل می‌شوند.
- اسلات دستگاه، Fingerprint و فرصت انتقال تغییر نمی‌کند.
- پاسخ API با کد `403` و شناسه `launcher_account_suspended`، علت و زمان پایان را برای نمایش در صفحه ورود برمی‌گرداند.
- محرومیت زمان‌دار پس از رسیدن زمان پایان، هنگام درخواست بعدی خودکار بی‌اثر می‌شود و به Cron نیاز ندارد.
- پس از رفع محرومیت، کاربر باید یک‌بار آنلاین وارد لانچر شود.

همان محدودیت ذاتی مجوز آفلاین درباره محرومیت نیز وجود دارد: کاربری که از قبل مجوز آفلاین معتبر دارد و هیچ اتصالی به سرور ندارد، تا پایان همان مجوز (حداکثر ۷ روز) قابل قطع آنی نیست.

## انتشار روی سرور

پس از جایگزینی سورس، در محیط Production اجرا شود:

```bash
php artisan migrate --force
php artisan optimize:clear
```

سپس Workerهای صف و PHP-FPM طبق روش استقرار سرور Restart شوند.

## آزمون پذیرش

1. محرومیت ۱۰ روزه اعمال شود؛ ورود رمز و OTP لانچر باید علت و زمان پایان را نمایش دهد.
2. محرومیت دائمی اعمال شود؛ پیام باید دائمی بودن را نمایش دهد.
3. کاربر محروم همچنان باید بتواند وارد وب‌سایت شود.
4. Token فعال پیش از محرومیت باید در اولین درخواست آنلاین با `403` رد شود.
5. رفع محرومیت انجام شود؛ ورود آنلاین مجاز شود و سهمیه دستگاه قبلی حفظ گردد.
6. Reset دستگاه انجام شود؛ دستگاه بعدی به‌عنوان اسلات اول ثبت شود و خریدها باقی بمانند.
