# حفظ دسترسی خریدهای قبلی پس از ناموجود شدن نسخه فروش

این اصلاح مربوط به تغییر `ProductSaleItem.status` از `available` به `unavailable`
است. خاموش کردن انتشار در لانچر (`launcher_enabled`)، حذف آیتم یا لغو دسترسی خرید،
عملیات جداگانه‌اند و رفتار آن‌ها تغییر نکرده است.

## نتیجه بررسی

- حساب کاربری سایت: فهرست خریدها، فعال بودن دکمه دانلود و دریافت فایل به اعتبار
  `PurchaseAccess` وابسته‌اند؛ ناموجود شدن نسخه فروش مانع دانلود قبلی نیست.
- API کتابخانه، manifest، دانلود پایه، مادها، آپدیت‌ها و مجوز آفلاین نیز شرط
  موجود بودن نسخه فروش ندارند و دسترسی معتبر را حفظ می‌کنند.
- مشکل در کاتالوگ لانچر بود: فهرست فقط `available` را برمی‌گرداند، حتی برای خریدار.
  جزئیات مستقیم محصول از قبل آیتم ناموجود را می‌پذیرفت، اما وضعیت دکمه‌های خرید و
  دریافت رایگان، موجودی را بررسی نمی‌کرد. تغییر موجودی نیز کش کاتالوگ را پاک نمی‌کرد.

## اصلاح

- کاتالوگ علاوه بر محصولات موجود، نسخه‌های ناموجودی را برمی‌گرداند که کاربر برای
  همان نسخه، دسترسی معتبر لانچر دارد. جستجو، مرتب‌سازی و صفحه‌بندی همچنان در SQL
  انجام می‌شوند؛ خرید نسخه‌ای دیگر از همان محصول، این نسخه را باز نمی‌کند.
- شناسه نسخه‌های ناموجود قابل دسترس در هر درخواست دوباره محاسبه می‌شود و در کلید
  کش دخالت دارد؛ کش مشترک خریدار به کاربر دیگر یا دسترسی منقضی/لغوشده منتقل نمی‌شود.
- `can_buy` و `can_claim` برای آیتم ناموجود خاموش‌اند. شروع checkout جدید نیز با
  HTTP 422 رد می‌شود؛ checkout خریدار قبلی همچنان شناسه دسترسی موجود را برمی‌گرداند.
- تغییر موجودی کش را تازه می‌کند، بدون افزایش `manifest_revision` یا باطل کردن
  نشست‌های دانلود در حال اجرا. کنترل خرید در سبد سایت و دریافت رایگان حفظ شده است.

## اعتبارسنجی محلی

فایل `tests/Feature/Launcher/UnavailableSaleItemAccessTest.php` شامل ۱۵ تست و ۷۳
assertion موفق است: کش گرم و بازگشت موجودی، تفکیک کاربران و نسخه‌ها، جستجو و
صفحه‌بندی، دسترسی منقضی/لغوشده/آینده، ادعای رایگان نامعتبر، دانلود سایت، کتابخانه،
manifest نصب و اجرا، دانلود تازه و ادامه دانلود، ماد و آپدیت، مجوز آفلاین و جلوگیری
از خرید جدید. تست مجوز از کلید موقت در حافظه استفاده می‌کند.

با اجرای همان تست‌های جدید روی کد قبل از اصلاح، ۹ مورد شکست خورد؛ روی کد اصلاح‌شده
همه موفق‌اند. همراه تست‌های StagingUpdates، GameGateManifest و Unitهای Catalog و
Launcher، مجموعاً ۳۸ تست و ۱۹۳ assertion موفق‌اند.

```powershell
php vendor/phpunit/phpunit/phpunit tests/Feature/Launcher/UnavailableSaleItemAccessTest.php
```

اجرای گسترده‌تر با خطاهای مستقل در تست‌های آپلود رسانه و mock تنظیمات bootstrap
مواجه شد؛ این خطاها روی کد قبل از اصلاح نیز بازتولید شدند. تست‌های متکی بر تمام
migrationها نیز با دستور MySQL `ALTER TABLE ... MODIFY` روی SQLite متوقف می‌شوند.
تست مسیرهای لانچر نیز به مسیر ثبت‌نشده `api.v1.library.content.files.download` اشاره
می‌کند. این موارد در این اصلاح تغییر نکرده‌اند.

برای این تغییر migration جدیدی لازم نیست. تست مستقیم برنامه نصب‌شده لانچر و
سرور عملیاتی انجام نشده است؛ بررسی و اصلاح در این مخزن، سمت سرور و قرارداد API است.
پس از استقرار، یک نسخه خریداری‌شده را ناموجود کنید و پس از تازه‌سازی لانچر، باز شدن
محصول، دانلود و اجرای آن را روی کلاینت نیز بررسی کنید.
