# دسترسی‌های پنل فروشندگان

در پنل مدیریت، صفحه ایجاد یا ویرایش هر فروشگاه، بخش **دسترسی‌های پنل فروشندگان** در دسترس است. تنظیمات برای تمام کاربران فروشنده متصل به همان فروشگاه اعمال می‌شوند. دسترسی فروشگاه‌های دیگر مستقل است.

| تنظیم | اثر |
| --- | --- |
| ورود به پنل | دسترسی به تمام صفحات پنل آن فروشگاه را فعال یا مسدود می‌کند. |
| نمایش تعداد فروش و سفارش‌ها | تعداد سفارش، فروش محصول و افزونه را در داشبورد و محصولات کنترل می‌کند. در حالت خاموش، ریز فروش هم بسته است تا تعداد ردیف‌ها آمار را آشکار نکند. |
| نمایش درآمد و مبالغ فروش | مبالغ کل و تفکیکی، نمودار درآمد و اطلاعات مالی را کنترل می‌کند. در حالت خاموش، درخواست وجه هم بسته است. |
| نمایش اطلاعات خریداران | در حالت خاموش، تیکت‌ها، دیدگاه‌ها و تصاویر پیوست در پنل فروشنده بسته‌اند، چون متن و تصویر ممکن است اطلاعات شخصی داشته باشند. ریز فروش همچنان شماره سفارش را بدون اطلاعات هویتی خریدار نشان می‌دهد، مشروط به فعال بودن دسترسی ریز فروش. |
| مشاهده ریز فروش | صفحه جزئیات نسخه‌ها، افزونه‌ها و ردیف سفارش‌ها؛ نیازمند نمایش تعداد فروش است. |
| نمایش کمیسیون | درصد سهم فروشگاه، نرخ مؤثر و سهم پلتفرم در گزارش‌ها؛ نمایش مبالغ نیازمند دسترسی درآمد است. |
| مشاهده دیدگاه‌ها | نیازمند نمایش اطلاعات خریداران است. |
| مشاهده تیکت‌ها و پیوست‌ها | نیازمند نمایش اطلاعات خریداران است. |
| پاسخ‌گویی به تیکت‌ها | نیازمند مشاهده تیکت‌ها است؛ خاموش کردن آن تیکت‌ها را فقط خواندنی می‌کند. |
| مشاهده و ثبت درخواست وجه | نیازمند نمایش درآمد است. |

دسترسی وابسته فقط در صورت فعال بودن همه پیش‌نیازها مؤثر است. وضعیت انتخاب‌شده آن ذخیره می‌ماند؛ با فعال شدن دوباره پیش‌نیاز، انتخاب قبلی اعمال می‌شود.

## سازگاری و حریم خصوصی

- برای حفظ رفتار فعلی، دسترسی‌ها در فروشگاه‌های موجود و فروشگاه‌های جدید به‌صورت پیش‌فرض فعال‌اند.
- تنظیم «عدم نمایش تعداد فروش» در بخش «تنظیمات نمایش عمومی سایت» همچنان مستقل است و نمایش عمومی سایت را کنترل می‌کند؛ تنظیمات جدید برای پنل فروشنده هستند.
- بررسی دسترسی در سرور انجام می‌شود. وارد کردن نشانی مستقیم صفحات یا تصاویر، یا ارسال مستقیم درخواست پاسخ/برداشت، محدودیت را دور نمی‌زند.
- داده‌های ممنوع از گزارش ارسالی به قالب حذف یا تهی می‌شوند. snapshot و metadata سفارش به ریز فروش ارسال نمی‌شوند. نمودار درآمد پنهان‌شده در HTML قرار نمی‌گیرد.
- پاسخ‌های صفحات فروشگاه `private, no-store` هستند. تغییر دسترسی در درخواست بعدی اعمال می‌شود؛ اطلاعاتی که قبلاً مشاهده یا ذخیره شده‌اند قابل پس‌گرفتن نیستند.
- دسترسی مشتری به تیکت متعلق به خودش و دسترسی مدیر مجاز به پشتیبانی مستقل از نقش فروشندگی باقی می‌ماند.

## استقرار

تنظیمات در ستون JSON به نام `stores.seller_permissions` ذخیره می‌شوند. هنگام استقرار، migration و build را اجرا کنید:

```sh
php artisan migrate
npm run build
```

تست‌های مرتبط با SQLite حافظه‌ای اجرا می‌شوند:

```sh
php artisan test --compact tests/Feature/Marketplace tests/Feature/Support
```
