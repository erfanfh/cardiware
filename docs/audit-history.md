# Audit history

`AuditServiceProvider` records Eloquent `created`, `updated`, `deleted`, and `restored` events for every model under `App\Domain`. A new domain model needs no registration. Models outside that namespace can use the `Auditable` trait. `AuditEvent` is excluded to prevent recursive logs.

Rows keep the subject type and ID, event type, actor ID and name at the time of the action, and the event timestamp. A missing actor ID is labeled `guest` for web requests or `system` for console work. Creation and deletion store one sanitized snapshot. Updates store only changed attributes in `old_data` and `new_data`; timestamp only updates produce no row. Passwords, tokens, secrets, and hidden model attributes are omitted. A model can implement `auditExcludedAttributes(): array` for additional sensitive or redundant fields.

Many-to-many writes must use `AuditService::sync($model, 'relation', $ids)` or `AuditService::detach($model, 'relation', $ids)`. Pass `false` as the fourth `sync` argument for `syncWithoutDetaching` behavior. These methods record added, removed, and changed pivot rows, and run the write and its audit records in one transaction. New relation writers should use these methods instead of calling Eloquent `sync`, `attach`, or `detach` directly.

Eloquent mass `update`, `delete`, `increment`, raw `DB::table` writes, and `insert` do not dispatch per-model events. For audited domain data, load the affected models and call their instance methods inside a transaction. When an atomic SQL update is necessary, retain its previous values and call `AuditService::recordChange($model, $before, $after)` inside the same transaction. Changes made before this module was installed are not backfilled.

The admin panel exposes **Reports → Change history** at `/admin/audit-events`. Only users with `audit.view` can open the list or detail page. The permission migration creates the ability, but administrators must grant it to the appropriate roles. The list filters by event type, subject type/ID/title, actor ID, and a Jalali date range. Its detail page compares only recorded fields, shows relationship metadata, and links to other events for the same subject. The subject label and actor name are saved with each event so a deleted subject or actor remains identifiable. Add Persian names for new subject types or fields to `config/audit-history.php`; an unmapped name falls back to a readable model or field name.
