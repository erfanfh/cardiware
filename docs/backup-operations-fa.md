# راهنمای عملیاتی بک‌آپ مودینگ‌وی

## سیاست پیش‌فرض

- بک‌آپ دیتابیس اصلی هر ۶ ساعت و بک‌آپ کامل هر ۲۴ ساعت اجرا می‌شود.
- بک‌آپ کامل شامل کل ریشه پروژه، `.env`، فایل‌های `storage/app` و `public/wp-content` است.
- `vendor`، `node_modules`، `.git`، build، cache و log حذف می‌شوند؛ این موارد از کد و lock file قابل بازتولیدند.
- آرشیوها با AES-256 رمزگذاری و در disk خصوصی `parspack_backup` ذخیره می‌شوند.
- پاک‌سازی روزانه ساعت ۰۴:۱۰ به وقت تهران انجام می‌شود و مصرف را حداکثر روی ۱۴۰ گیگ نگه می‌دارد.

## آماده‌سازی سرور

1. وابستگی‌ها را با `composer install --no-dev --optimize-autoloader` نصب کنید.
2. متغیرهای `PARSPACK_BACKUP_*` و `BACKUP_ARCHIVE_PASSWORD` را مطابق `.env.example` در env تولید تنظیم کنید. رمز آرشیو باید تصادفی، حداقل ۳۲ کاراکتر و در password manager آفلاین نیز نگه‌داری شود.
3. `php artisan migrate --force` و سپس `php artisan optimize:clear` را اجرا کنید.
4. مطمئن شوید `mysqldump`، PHP ZIP و فضای موقت حداقل برابر حجم داده‌های بک‌آپ روی سرور موجود است.
5. worker صف باید queue پیش‌فرض را مصرف کند. در صورت استفاده از Horizon، supervisor مربوط به `default` را فعال نگه دارید.
6. cron استاندارد Laravel باید هر دقیقه اجرا شود:

   ```cron
   * * * * * cd /path/to/moddingway && php artisan schedule:run >> /dev/null 2>&1
   ```

7. در پنل «تنظیمات سایت ← بک‌آپ خودکار»، وضعیت همه پیش‌نیازها را بررسی، یک بک‌آپ دستی کامل اجرا و پس از موفقیت حالت خودکار را فعال کنید.

## آزمون بازیابی الزامی

بک‌آپی که بازیابی آن آزمایش نشده قابل اعتماد نیست. حداقل ماهی یک‌بار آخرین ZIP را روی یک سرور staging دانلود کنید، با رمز آرشیو باز کنید، `.env` را با مقادیر staging جایگزین کنید، `composer install` و import دیتابیس را انجام دهید و مسیرهای اصلی سایت و فایل‌های آپلودی را بررسی کنید. هیچ بازیابی‌ای را مستقیماً روی production و از داخل پنل وب انجام ندهید.

## پایش

- سوابق queued/running/succeeded/failed در جدول `backup_runs` و صفحه مدیریت نمایش داده می‌شود.
- اگر رکوردی بیش از ۱۲ ساعت در صف یا بیش از ۳ ساعت در حال اجرا بماند، اجرای بعدی آن را failed علامت می‌زند.
- برای تشخیص ازکارافتادن کامل سرور یا cron، یک مانیتور بیرونی مستقل لازم است؛ پایش داخل همان برنامه نمی‌تواند خرابی کامل خودش را گزارش کند.
- کلید Object Storage بهتر است فقط دسترسی همان bucket را داشته باشد. Versioning/Object Lock پارس‌پک، در صورت پشتیبانی پلن، یک لایه محافظ جدا در برابر حذف یا باج‌افزار ایجاد می‌کند.
