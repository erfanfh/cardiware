# راهنمای استقرار Laravel برای MW Launcher 1.21.0

## تغییرات این بسته

- سفارش لغوشده، برگشتی، منقضی یا Revoked دیگر مالکیت معتبر محسوب نمی‌شود.
- سابقه دسترسی لغوشده، خرید مجدد همان محصول را مسدود نمی‌کند.
- API فیلد صریح `ownership.has_access` را به لانچر می‌دهد.
- صفحه عمومی `Cardiware.ir/launcher` برای معرفی و دانلود لانچر اضافه شده است.
- صفحه واسط بازکردن محصول در لانچر اضافه شده است.
- نتیجه پرداختی که از لانچر شروع شده، به‌صورت امن به لانچر بازمی‌گردد.
- رسید خرید سایت برای محصولات فعال در لانچر، دکمه «باز کردن در لانچر» دارد.

## اقدامات برنامه‌نویس Laravel

1. همه فایل‌های این سورس را با حفظ فایل‌های محیطی و Uploadهای سرور Deploy کند.
2. کش‌های Laravel را پاک و دوباره بسازد:

   ```bash
   php artisan optimize:clear
   php artisan config:cache
   php artisan route:cache
   php artisan view:cache
   ```

3. آدرس فایل نصب عمومی لانچر را در `.env` قرار دهد:

   ```dotenv
   LAUNCHER_PUBLIC_DOWNLOAD_URL=https://download.example.com/MWLauncher-Setup.exe
   ```

   این متغیر مخصوص صفحه `/launcher` است. متغیر `LAUNCHER_DOWNLOAD_URL` همچنان برای بسته آپدیت خودکار لانچر استفاده می‌شود و نباید جای این فایل قرار بگیرد.

4. اگر از CDN یا هاست دانلود استفاده می‌شود، لینک `LAUNCHER_PUBLIC_DOWNLOAD_URL` باید HTTPS و قابل دانلود عمومی باشد.
5. مسیرهای زیر را بررسی کند:

   - `GET /launcher`
   - `GET /launcher/open/product/{saleItemId}`
   - `GET /launcher/purchase-complete` (فقط با لینک امضاشده)

## تست نهایی مشترک

1. سفارش یک کاربر را لغو کنید؛ API کاتالوگ باید برای محصول `has_access: false` و `can_buy: true` برگرداند.
2. خرید مجدد همان محصول باید مجاز باشد.
3. خرید را از دکمه داخل لانچر شروع و پرداخت را کامل کنید.
4. صفحه موفق سایت باید صفحه واسط را نشان دهد و MW Launcher را باز کند.
5. در رسید یک خرید عادی سایت، دکمه «باز کردن در لانچر» باید همان Sale Item را باز کند.
6. روی سیستمی که لانچر نصب نیست، صفحه واسط باید لینک دانلود `/launcher` را در اختیار کاربر بگذارد.

## نکته امنیتی

لینک برگشت پرداخت دارای State یک‌بارمصرف، تاریخ انقضا، امضای Laravel و تطبیق حساب/دستگاه است. مالکیت نهایی فقط در API لانچر و با `PurchaseAccess::isUsable()` تأیید می‌شود؛ وجود فایل نصب‌شده یا یک سفارش تاریخی باعث بازشدن محصول نمی‌شود.
