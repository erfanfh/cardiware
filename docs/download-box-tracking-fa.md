# شمارش تقریبی کلیک‌های باکس دانلود

عنوان لینک، دکمهٔ دانلود و کپی لینک همگی آدرس مستقیم فایل را استفاده می‌کنند. هنگام کلیک روی عنوان یا دکمهٔ دانلود، یک درخواست POST جداگانه برای ثبت آمار ارسال می‌شود. مسیر دریافت فایل هیچ ریدایرکت یا وابستگی به ثبت آمار ندارد؛ دانلود چندبخشی و Resume مانند لینک مستقیم قبلی کار می‌کنند.

ارسال با `navigator.sendBeacon` و در صورت نبود پشتیبانی، خطا یا نپذیرفتن درخواست، با `fetch` و `keepalive: true` انجام می‌شود. handler کلیک، `preventDefault` ندارد، منتظر پاسخ سرور نمی‌ماند و خطاهای درخواست آمار را نادیده می‌گیرد. کلیک وسط هم با `auxclick` ثبت می‌شود؛ کلیک راست شمرده نمی‌شود. برای جلوگیری از ارسال‌های سریع تکراری از یک لینک، در مرورگر فاصلهٔ حداقل دو ثانیه اعمال می‌شود.

آدرس `POST /dl/e/{publicId}/click` در قالب با امضای نسبی Laravel تولید و با `signed:relative` بررسی می‌شود. بنابراین endpoint بدون session، ورود، middlewareهای بازدید صفحه و ریدایرکت‌های SEO کار می‌کند و درخواست فاقد امضای معتبر پذیرفته نمی‌شود. امضا به آدرس ثبت آمار تعلق دارد و داخل آدرس فایل یا لینک کپی‌شده نیست. پاسخ موفق `204 No Content` و غیرقابل‌کش است.

## تعریف آمار و فشار روی سرور

- آمار، کلیک روی لینک دانلود در سایت است؛ شروع واقعی، صحت یا کامل‌شدن دریافت فایل بررسی نمی‌شود.
- کپی لینک و دانلود بعدی از clipboard، دانلود منیجرهایی که کلیک صفحه را اجرا نمی‌کنند، دانلود با منوی راست‌کلیک، Resume و درخواست‌های فایل GET/HEAD/Range شمرده نمی‌شوند. JavaScript غیرفعال، مسدودکنندهٔ درخواست آمار یا قطع شبکه هم می‌تواند باعث کم‌شماری شود. کلاینت‌های خودکار دارای امضای معتبر ممکن است روی آمار اثر بگذارند.
- هر ترکیب لینک و IP در بازهٔ پیش‌فرض ۳۰ دقیقه یک‌بار شمرده می‌شود. IP با HMAC ذخیره می‌شود و متن IP در کلید Redis نیست. User-Agent و کوکی جزو کلید نیستند.
- تکرار کلیک یا کاربران پشت IP مشترک در این بازه ممکن است کمتر شمرده شوند. کلیک پس از پایان بازه یا تغییر IP ممکن است دوباره شمرده شود.
- هر درخواست ثبت کلیک فقط یک SELECT با شناسهٔ عمومی ایندکس‌شده و یک عملیات اتمیک Lua در Redis دارد. هیچ نوشتن دیتابیس، درخواست به سرور فایل، دانلود آزمایشی یا job جداگانه برای هر کلیک انجام نمی‌شود. درخواست‌های دریافت فایل هیچ کاری روی سایت برای شمارش انجام نمی‌دهند.
- برای هر لینک دارای آمار جدید، یک افزایش جمعی شمارنده در هر نوبت انتقال انجام می‌شود. آمار در پنل مدیریت، پس از انتقال در ستون موجود `download_entries.download_click_count` دیده می‌شود. جدول یا migration جدید لازم نیست.

## انتقال و تحمل خطا

اسکریپت ثبت Redis، بررسی تکرار، افزایش شمارنده و ثبت dirty marker را اتمیک انجام می‌دهد. دستور `app:transfer-download-clicks-to-database` با قفل مشترک Redis و تمدید آن، ابتدا snapshot شمارنده را به SQL اضافه می‌کند و سپس فقط همان مقدار را از Redis کم می‌کند. درخواست‌های رسیده حین ذخیره باقی می‌مانند. شکست SQL، بافر را حذف نمی‌کند. دستور قدیمی `downloads:flush-clicks` به همین دستور واگذار می‌شود و شمارنده‌های هر دو ساختار قدیمی Redis منتقل می‌شوند.

این آمار تقریبی است و انتقال بین Redis و SQL تراکنش مشترک ندارد: اگر پردازش دقیقاً بعد از موفقیت SQL و قبل از تأیید Redis قطع شود، snapshot ممکن است در اجرای بعدی دوباره اضافه شود. پاک‌شدن Redis یا eviction شمارنده‌ها هم می‌تواند آمار منتقل‌نشده را از بین ببرد. برای این کاربرد، جدول رسید یا لاگ هر درخواست اضافه نشده است.

خرابی ثبت آمار هیچ اثری بر لینک دانلود ندارد. اتصال اختصاصی `download_counters` همان Redis DB و prefix قبلی را با timeout پیش‌فرض ۰٫۲۵ ثانیه و بدون retry استفاده می‌کند. کلیک‌هایی که هنگام قطعی Redis یا دیتابیس ارسال می‌شوند ممکن است از آمار جا بمانند.

## راه‌اندازی

1. Redis باید فعال باشد. تنظیمات اختیاری: `CACHE_DOWNLOAD_CLICKS_DEDUP_MINUTES=30`، `REDIS_DOWNLOAD_COUNTER_TIMEOUT=0.25`، `CACHE_DOWNLOAD_CLICKS_SCHEDULE=1` و `CACHE_DOWNLOAD_CLICKS_FLUSH_LIMIT=10000`.
2. پس از انتشار، `npm run build` را اجرا و config، view و route cache را مطابق روال پروژه بازسازی کنید. درخواست POST ثبت آمار نباید در CDN یا reverse proxy کش شود.
3. Laravel Scheduler باید هر دقیقه اجرا شود. زمان‌بندی انتقال از قبل در `SchedulerServiceProvider` موجود است؛ نیاز به queue worker جدید نیست.
4. برای انتقال دستی: `php artisan app:transfer-download-clicks-to-database --limit=10000`.
5. پروکسی واقعی سایت باید در trusted proxies تعریف شده باشد تا IP درست دریافت شود. به `X-Forwarded-For` از پروکسی‌های ناشناس اعتماد نکنید.

## آزمایش

`php artisan test --filter=DownloadEntryTrackingTest` endpoint امضاشدهٔ POST، رد درخواست‌های بدون امضا یا دست‌کاری‌شده، عدم نوشتن SQL، نبود وابستگی session، خطای Redis، لینک‌های غیرعمومی و لینک مستقیم قالب را بررسی می‌کند.

`node --test tests/Frontend/download-box.test.mjs` ارسال beacon، fallback با keepalive، عدم انتظار برای پاسخ، عدم لغو کلیک، خطاها، کلیک وسط و حذف درخواست‌های سریع تکراری را بررسی می‌کند.

تست‌های Lua و انتقال با Redis واقعی و prefix تصادفی اجرا می‌شوند. متغیر `DOWNLOAD_COUNTER_TEST_REDIS_PORT` را به پورت Redis آزمایشی محلی بدهید و `php artisan test --filter=DownloadClickCounterTest` را اجرا کنید. دیتابیس تست SQLite در حافظه است؛ هیچ `FLUSHDB` روی Redis انجام نمی‌شود.

برای بررسی دستی، در DevTools لینک مقصد و clipboard را کنترل کنید: باید همان آدرس اصلی فایل باشند. کلیک روی عنوان یا دکمه باید یک POST جداگانه ثبت کند، بدون تغییر یا انتظار در مسیر دانلود. دانلود با JavaScript غیرفعال و با شکست endpoint آمار هم باید از همان آدرس مستقیم شروع شود. برای بررسی IDM/FDM، فایل مستقیم را دانلود و توقف/ادامه کنید؛ هیچ URL رهگیری در مسیر فایل نباید باشد. تست‌های خودکار جای اجرای واقعی کلاینت IDM را نمی‌گیرند.
